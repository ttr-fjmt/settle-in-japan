# Settle in Japan

外国人が日本で暮らしはじめるための情報ポータル（企画・開発中）。公開予定は settle-in-japan.net。
在留資格・手続き・住まい・仕事の情報を、**公式ページの本文と照合したものだけ**、多言語で提供する。

図鑑シリーズ（転職エージェント図鑑 / フリーランス案件図鑑 / スキルアップ図鑑）の4サイト目。
運営の型は同じだが、扱うのが法律・行政手続きの情報なので、データの扱いは他3サイトより厳しくしている。

- 方針・判断：[CLAUDE.md](CLAUDE.md) / [PROJECT_CONTEXT.md](PROJECT_CONTEXT.md) / [DECISIONS.md](DECISIONS.md)
- データ品質：[DATA_QUALITY_POLICY.md](DATA_QUALITY_POLICY.md)

## いまある状態

最初に作るのは**在留資格図鑑**（在留資格の比較表）。現時点では、**データを載せるための土台だけ**がある。

| 場所 | 中身 |
|---|---|
| `data/sources.json` | 出典にする公式ページの一覧（出入国在留管理庁など） |
| `data/raw/` | 公式ページの本文。`fetch-official.js` が保存する。手で編集しない |
| `data/visa-types.json` | 在留資格のデータ。**33件**（29種類。高度専門職・特定技能・技能実習は号ごと） |
| `scraper/lib/schema.js` | データの形と許容値。分類を増やすときはここだけを変える |
| `scraper/lib/verify.js` | 本文照合。書いた文言が公式ページに実在するかを確かめる |
| `scraper/fetch-official.js` | 公式ページを取得して `data/raw/` に保存する |
| `scraper/extract-visa-types.js` | 保存した本文から `data/visa-types.json` を組み立てる |

## なぜ「取得」と「データ作り」を分けているか

クラウド（Claude Code on the web）のセッションは、環境で許可されたドメインしか見られない。
`moj.go.jp` は許可されていないため、**セッションから公式ページを直接読めない**。
一方 GitHub Actions からは外部サイトにアクセスできる。そこで：

1. **Actions が取得する** — `.github/workflows/fetch-official.yml` を手動実行すると、
   `data/sources.json` のページを取得し、本文を `data/raw/<id>.txt` に保存してコミットする
2. **セッションがそれを読んでデータを作る** — `data/raw/` はリポジトリの中なので読める。
   本文に無いことは書かない

この形なら、書いた内容が公式ページと一致しているかを、あとから何度でも機械的に確かめられる。

## 本文照合（このリポジトリの要）

`data/visa-types.json` に書く在留期間や活動内容は、**公式ページの本文にある文言をそのまま**使う。
`npm test` が、その文言が `data/raw/` の本文に実在するかを照合する。

言い換える（例：「5年」→「最長5年」）と照合に落ちる。**それが狙い。**
AIに「本文に無いことを書かないで」と指示するだけでは守られないことが、既存3サイトで分かっているため。

## コマンド

```bash
cd scraper
npm test            # ユニットテスト（データの形・出典・本文照合・表現のチェック）
npm run validate    # data/visa-types.json を検証
npm run fetch       # 公式ページを取得（※通信が必要。ふつうは Actions で動かす）
npm run extract     # 保存した本文から visa-types.json を作り直す（--dry-run で確認だけ）
```

依存パッケージは無い（Node 22 の標準機能だけ）。`npm install` は不要。

## 今の決まりごと

- **出典は公式ドメインだけ**（`moj.go.jp` `mhlw.go.jp` など）。個人ブログ・事務所サイトは出典にしない
- **全レコードに出典URLと最終確認日が要る**。無いとテストが落ちる
- **確認できない項目は `unknown` のまま**にして、`review_flags` に理由を残す
- **個別の相談には答えない。** 「あなたは申請できます」のような表現はテストで止める
  （行政書士・弁護士の資格が必要な領域に踏み込まないため）
