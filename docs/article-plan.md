# 記事の題材リスト（100本）

Settle in Japan に載せる解説記事の計画。**書く前に題材を出し切って、公式情報で裏が取れるかを見極めるための一覧。**

## この一覧の使い方（守ること）

- **1記事2000字程度。** 公式ページで確認できたことだけを書き、出典と最終確認日を必ず載せる
- **「根拠」の欄にある機関の公式ページを取得してから書く。** 取得していない題材は書かない。
  取得は `.github/workflows/fetch-official.yml`（`data/sources.json` に追加してから実行）
- **公式ページで裏が取れなかった題材は、書かずに飛ばす。** 埋めるために推測しない。
  飛ばしたときは、この一覧の該当行に「書けなかった理由」を追記する
- **個別の相談には答えない。** 「あなたの場合は◯◯できます」ではなく「制度はこうなっている（出典）」と書く。
  手続きの可否や期限の個別判断は、記事の末尾から公式窓口（外国人在留支援センター等）へ案内する
- **金額・期限・割合は、公式ページに書かれている数字だけ。** 相場・目安は書かない

## この一覧と、自動更新の関係

この一覧は**人が読むためのもの**。同じ題材を機械が読める形にしたものが
[data/article-queue.json](../data/article-queue.json) で、毎日の自動更新
（`.github/workflows/publish-article.yml`）はそちらを上から順に処理する。
題目がずれていないかは `npm test` が見張っている（`test/article-queue.test.js`）。

## 公開のペース

- **最初の5本**（AdSense 申請用）を先に出す。下の「最初に書く5本」の印がついたもの
- そこから **100本に達するまで1日1本**（日本時間6:00 に自動）
- **101本目からは週1本**

題材が尽きた場合は、勝手に薄い記事を作らず止める。この一覧に無い題材を追加するときは、
先に「公式で裏が取れるか」を確かめてからこの一覧に足す。

## 最初に書く5本（AdSense 申請用）

AdSense の審査では「有用性の低いコンテンツ」と判定されないことが最優先。
**検索されている量が多く、公式情報で確実に裏が取れ、読んだ人がその日のうちに行動できる**題材を選んだ。

1. **来日後14日以内にやること**（#16）
2. **住民登録（転入届）の手順**（#17）
3. **在留カードの役割と、いつ受け取るか**（#18）
4. **国民健康保険の入り方**（#19）
5. **住所が変わったときの届出**（#20）

5本とも「来日直後」に集まっている。同じ時期の悩みでまとまっているため、
記事どうしを行き来させやすく、サイトの入口としても筋が通る。

## 出典の追加が必要な題材

上の表で「出典の追加が必要」と書いた題材は、まだ `data/sources.json` に公式ページを登録していない。
書く前に登録して取得すること。登録先の候補：

税関 / 警察庁 / 金融庁 / 消防庁 / 文化庁 / 内閣府 / 消費者庁 / 法テラス / 各国大使館
